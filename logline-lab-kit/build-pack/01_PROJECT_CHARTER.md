# Project Charter

## Name

```txt
logline-lab-kit
```

## One sentence

**LogLine Lab Kit is an installable Act machine.**

## Purpose

LogLine Lab Kit lets a user instantiate a Lab: a place where Acts can be emitted, validated, stored, projected, blocked, evidenced, receipted, reported, and eventually executed through governed workers.

## Non-goals

LogLine Lab Kit is not:

```txt
LogLine Foundation
Santo André Lab
Manhattan
minilab.work
Dan Control Plane
Pitwall
Cockpit
Hermes
OpenClaw
Supabase
Cloudflare
```

Those may appear as references, packs, apps, profiles, runtimes, or deployments.
They do not define the generic product.

## The architecture law

```txt
Act is the canonical unit.
Everything else is envelope, convention, projection, pack, profile, app, runtime, or deployment.
```

## The shipping law

```txt
Core must be generic.
Packs may be opinionated.
Profiles may choose infrastructure.
Apps may expose interfaces.
Runtimes may execute.
Deployments may name real machines.
```

## The proof law

```txt
Claim is not evidence.
Execution is not success.
Report is not receipt.
Receipt closes only declared scope.
```
